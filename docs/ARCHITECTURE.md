# Spirit Derby — Architecture & API Contract

This document is the authoritative interface contract between the **core** (DOM-free game logic under `js/`) and the **UI** (`js/ui/*`, `index.html`, `css/*`). Agents building either side must conform to it exactly. If something here is impossible, change the code AND this file, and say so in your report.

## Ground rules

- Vanilla JS, no build step, no dependencies. Must run from `file://` by double-clicking `index.html`.
- **No ES modules.** Every file is one IIFE attaching to a namespace:
  ```js
  (function (SD) {
    'use strict';
    // ...
    SD.race = { simulate, buildEntrants, selectField, phaseOf, hashRecord, PHASES };
  })(globalThis.SD = globalThis.SD || {});
  ```
- Core files (`js/*.js`, not `js/ui/`) may reference only `SD.*`, `Math`, `JSON`, `Number`, `Array`, `Object`, `String`. No `window`, `document`, `Date`, `setTimeout`, `Math.random`, `crypto`. Time comes from `SD.clock.now()` (defined in `namespace.js`; UI/tests may override it); fresh randomness (seed salts, per-action rolls) comes only from `SD.entropy.next()` (review batch 5; installed by `main.js`, absent in Node/tests). `persistence.js` is the only core file allowed to touch `localStorage`, guarded by `typeof localStorage !== 'undefined'`, with an in-memory fallback.
- The race engine must be **deterministic**: all randomness from one `SD.rng.create(seed)` consumed in array order. `tools/load-core.js` replaces `Math.random` with a throwing function while tests run.
- Every number that tunes the game lives in `SD.CONFIG` (`js/config.js`). Catalog data lives in `SD.DATA` (`js/data.js`).
- Vocabulary: styles `frontRunner | paceChaser | lateSurger | wildCard`; stats `speed | stamina | power | wisdom | luck`; phases `START | EARLY | MID | FINAL_TURN | FINAL_STRETCH | FINISH`; conditions `Excellent | Good | Normal | Tired | Exhausted`; moods `Determined | Happy | Nervous | Fired Up | Sleepy | Chaotic`.

## Core API

### `SD` (namespace.js)
- `SD.VERSION` string, `SD.isNode` boolean.
- `SD.clock.now()` → ms epoch (default `Date.now()`); `SD.clock.set(fn)` to override.
- `SD.entropy.next()` → uint32 or `null` (review batch 5): the injected randomness source, like `SD.clock`. `set(fn)` installs `fn() → number` (low 32 bits used; a throw or a non-number counts as `null`), `reset()` / `set(null)` removes it, `available()`. **`js/main.js` installs `crypto.getRandomValues`** before boot; Node and the test suites install nothing, so they stay reproducible. See **Review fixes → Batch 5**.
- `SD.util`: `clamp(v, lo, hi)`, `round1(v)`, `pctString(v)`, `nameKey(str)` (lowercase, strips spaces/punctuation), `deepClone(obj)`, `redactSecrets(text)` (review batch 1: hides URL tokens / passwords as `…` before a URL is shown or exported), `hasOwn(obj, key)` / `own(obj, key)` / `setOwn(obj, key, value)` / `dict(src?)` (review batch 3: prototype-safe maps for keys from chat, the bridge or a save; see **Review fixes → Batch 3**).

### `SD.CONFIG` (config.js) — plain object; see plan §5–§6 for values.

### `SD.rng` (rng.js)
- `create(seed:uint32) → rng` with `float()`, `chance(p)`, `range(a,b)`, `int(n)` (0..n-1), `tri()` (−1..1 peaked at 0), `pick(arr)`, `weighted(items, weightOf)`, `seed` (the seed), `calls` (count, for debugging).
- `hash(str) → uint32` (FNV-1a). `seedFrom(...parts)` = `hash(parts.join(':'))`.

### `SD.DATA` (data.js)
- `ROSTER: RosterEntry[]` — the 10 named runners: `{ key, name, emoji, badgeColor, species, personality, description, style, stats:{speed,stamina,power,wisdom,luck}, abilityId }`.
- `SPECIES: { id: { name, emoji, badgeColor, statBias:{...}, styles:[...] } }` templates for random runners.
- `STYLES: { frontRunner: { name:'Front Runner', short:'FR', desc, vel:[5 numbers by phase], drain:[5] }, ... }`.
- `ABILITIES: { id: { name, desc, hook: 'phaseEntry'|'tick'|'overtake'|'passive'|'event', phase?, ...params } }`.
- `RACE_EVENTS: [ { id, name, phases:[...], target:'ALL'|'ONE'|'ONE_POS'|'ONE_NEG'|'LEADER'|'LAST', weight, severity, message (with {r} placeholder), effect:{...} } ]` — 16 entries.
- `DAY_EVENTS: [ { id, name, desc, modifiers:{...} } ]`.
- `MOODS: { 'Happy': { emoji, desc, vel, velPhases, sigma, drain, critMult, trainGain, trainCrit, trainFail, eventW, hypeMult } , ... }`.
- `CONDITIONS: [ [maxFatigue, label, raceMult, trainMult], ... ]`.
- `HYPE_THRESHOLDS: [ { value:25, id:'loud', text:'The crowd is getting loud!' }, { value:50, id:'feral', text:'CHAT HAS ENTERED FERAL MODE.' }, { value:100, id:'awakened', text:'THE FOREST HAS AWAKENED.' } ]`.
- `TRACK_NAMES: string[]`, `BADGE_PALETTE: string[]`, `TRAINING_FLAVOUR: { normal:{stat:[...]}, crit:[...], fail:[...] }`, `ACHIEVEMENTS: [ { id, name, desc, sp } ]`.

### `SD.bus` (bus.js)
- `on(name, fn) → unsubscribe`, `once(name, fn)`, `off(name, fn)`, `emit(name, payload)` (synchronous; listener exceptions are caught and `console.error`-ed), `wildcard(fn)`.
- `SD.EVENTS` — string constants: `STATE_CHANGED:'state:changed'`, `STATE_LOADED:'state:loaded'`, `SETTINGS_CHANGED:'settings:changed'`, `LOG_ENTRY:'log:entry'`, `RUNNER_SPAWNED`, `RUNNER_TRAINED`, `RUNNER_RESTED`, `RUNNER_CLAIMED`, `RUNNER_LEVELUP`, `RUNNER_CONDITION`, `PLAYER_JOINED`, `PLAYER_SP`, `HYPE_CHANGED`, `HYPE_THRESHOLD`, `BET_PLACED`, `BET_LOCKED` (review batch 4), `BET_RESOLVED`, `EVENT_DAY:'event:day'`, `RACE_STARTED`, `RACE_COUNTDOWN`, `RACE_FRAME`, `RACE_TICK`, `RACE_PHASE`, `RACE_EVENT`, `RACE_RUNNER_FINISHED`, `RACE_PAUSED`, `RACE_RESUMED`, `RACE_END_REQUESTED:'race:endRequested'`, `RACE_PLAYBACK_DONE:'race:playbackDone'`, `RACE_FINISHED`, `RACE_ABORTED`, `SEASON_DAY_ADVANCED`, `SEASON_ENDED`, `ACHIEVEMENT_UNLOCKED`, `CHAT_MESSAGE`, `COMMAND_RESULT`, `INTEGRATION_STATUS`. Values are the colon-separated lowercase names (`runner:trained`, `race:runnerFinished`, `season:dayAdvanced`, ...).

### `SD.state` (state.js)
- `create(opts?) → state` — fresh state per the plan §2 (10 roster runners spawned, `settings` defaults, `season` 1/1).
- `get() → state` (live object; UI must not mutate it), `set(state)` (**CHANGED in review batch 7**: leaves the mutate depth alone, so a `set()` inside a mutation no longer disables `state:changed` / autosave), `resetRuntime()` (review batch 7: clears every per-game runtime map; see **Review fixes → Batch 7**).
- `mutate(label, fn) → fn(state)` — runs `fn`, then bumps `meta.updatedAt`, calls `SD.persistence.scheduleSave()` if present, emits `state:changed {label}`. Nested mutates emit once (outermost). If `fn` throws, nothing is emitted and the error is rethrown. **CHANGED in review batch 6:** code inside the mutation may call `SD.state.saveHint('lazy' | 'none')`: `'lazy'` saves via `scheduleSave({ lazy: true })`, `'none'` (nothing changed) skips the save, the `updatedAt` bump and `state:changed`.
- `log(type, text, severity='info', extra?)` → appends to `state.log` (cap `CONFIG.LOG_CAP`), emits `log:entry`. `listTags(items, extra?) → { ...extra, usernames:[keys], runnerIds:[ids] }` (review batch 8 fix round 1) builds the tags of a line that names several viewers / runners (`items`: `[{ username, runnerId }]`).
- `runtime` — non-persisted object `{ cooldowns:{}, runnerCooldowns:{}, chatFeed:[], connected:{} }` (plus `activity`, `nervousCheers`, `hypeRecent`, `demoRunners` (review batch 8), `activeCommand`, `lastClockAt`, `hypeIdleAccumMs`). It survives `set()`; RESET ALL and IMPORT / RESTORE BACKUP clear the per-game maps (`resetRuntime`, review batch 7).
- Selectors: `runnerById(id)`, `findRunner(query) → { runner } | { ambiguous:[...] } | { none:true }` (case-insensitive; matches `nameKey`, exact then unique prefix; **CHANGED in review batch 8**: a name prefix and a word prefix are one tier, so a query two runners share is ambiguous, see **Review fixes → Batch 8**), `player(username)`, `activeRunners()` (not retired), `isRaceLocked()` (currentRace status in countdown/running/paused).

### `SD.persistence` (persistence.js)
- `KEY = 'spiritderby.save'`, `BACKUP_KEY`, `SCHEMA_VERSION` (**2** since M6; see **M6 additions**; **3** since review batch 2: `runner.ownerKey`, see **Review fixes → Batch 2**; **4** since review batch 6: slim history records, see **Review fixes → Batch 6**).
- `load() → { state, fromStorage, migratedFrom }` — returns a fresh state when nothing/corrupt is stored. Interrupted race (status not finished, or since review batch 7 a finished one `finishRace` could not apply) → bets refunded, `currentRace = null`, log entry. Review batch 5: `load()` / `importJSON()` re-salt `meta.seedSalt` from `SD.entropy` and clear a stored seed override; `exportJSON()` leaves out `meta.seedSalt` and the override (see **Review fixes → Batch 5**).
- `save(immediate?)`, `scheduleSave()` (debounced 500 ms via timers only in browser; immediate in Node; **CHANGED in review batch 6**: `scheduleSave({ lazy })`, read-only chat / clock ticks / a race in progress wait `CONFIG.SAVE.LAZY_MS`, and only the writer window saves), `flush()`, `exportJSON() → string`, `importJSON(text) → { ok, error?, migratedFrom?, ignoredConnection? }` (CHANGED in review batch 1: keeps this install's `settings.twitch` / `settings.bridge`), `clear()`, `migrate(raw) → state`, `MIGRATIONS` map.

### `SD.runners` (runners.js)
- `spawnFromRoster(entry, idx) → Runner`, `spawnRandom(rng, { name?, style?, speciesId? }) → Runner`, `statCap(level)`, `energyMax(level)`, `xpToNext(level)`, `addXp(runner, amount) → { levelUps:number, level }` (applies level-up effects), `conditionOf(fatigue) → label`, `refreshCondition(runner)` (sets `runner.condition`), `setMood(runner, mood)`, `clampRunner(runner)` (stats 1..cap, energy 0..max, fatigue 0..120), `perfScore(runnerLike, phase) → number` (uses `CONFIG.RACE.WEIGHTS`), `describe(runner) → string` (one-line summary for chat).
- Runner ids are `'r' + zero-padded counter` from `state.meta.runnerCounter`.

### `SD.training` (training.js)
- `train(state, runner, stat, { rng, by }) → { ok, outcome:'normal'|'crit'|'fail', gain, energyCost, message, hype, sp, xp }` — implements plan §6.2; throws nothing, returns `{ ok:false, message }` on invalid stat / energy < MIN.
- `rest(state, runner, { by, now }) → { ok, message, energyGain }` — respects per-runner rest cooldown in `state.runtime.runnerCooldowns`.
- `tickClock(state, elapsedMs)` — passive energy regen, fatigue decay, idle mood; returns list of changed runner ids.

### `SD.events` (events.js)
- `rollDayEvent(rng) → DayEvent`, `dayEventById(id)`, `raceEventsForPhase(phase) → RaceEvent[]`, `raceEventById(id)`.

### `SD.race` (race.js) — pure
- `PHASES = ['START','EARLY','MID','FINAL_TURN','FINAL_STRETCH','FINISH']`, `phaseOf(fraction) → phase`.
- `buildEntrants(runners, { hypeLevel, dayEvent, cheerBonus:{runnerId:n}, chatEffects? }) → Entrant[]` — snapshot incl. `perf` per phase, `stamMax`, `odds`, `lane` (1-based). Since review batch 4 the odds also read `hypeLevel` and the queued boosts / sabotages in `chatEffects` (see **Review fixes → Batch 4**).
- `selectField(state, count, rng) → Runner[]` — owned runners first, then by condition/energy; skips `energy < CONFIG.RACE.MIN_ENERGY_TO_RACE` unless not enough runners.
- `simulate({ id, seed, distance, entrants, eventFrequency, hypeLevel, dayEvent, chatEffects:[], trackName, season, day, indexInDay }) → RaceRecord`.
- `hashRecord(record) → string` (8-char hex FNV-1a of `JSON.stringify(results) + totalTicks + a digest of every event's tick/kind/runnerId`; results carry each runner's sub-tick `finishTick`, i.e. the final positions. Deliberately independent of `ticks` so records whose ticks were stripped from history still hash the same). Since review batch 5 `results[].levelUps` is hashed as `0` (the value at simulate time): `finishRace` fills it in afterwards, so `hashRecord(storedRecord) === storedRecord.hash` holds for every stored record.

**RaceRecord** (all serialisable):
```js
{ id, season, day, indexInDay, seed, distance, trackName, settingsSnapshot:{ eventFrequency, hypeLevel, dayEventId },
  entrants: [ { runnerId, name, emoji, badgeColor, ribbonColor, lane, style, abilityId, ownerAtRace /*label*/, ownerKeyAtRace /*login, batch 2*/, level,
                stats, condition, mood, energy, perf:{START,EARLY,MID,FINAL_TURN,FINAL_STRETCH}, stamMax, wildRoll, odds } ],
  ticks: [ { t, phase /*leader phase*/, pos: [ { id, d /*metres*/, v /*m per s*/, st /*stamina fraction 0..1*/, rank /*1-based*/, fx:[/*'crit','ability','fade','wall','event:<id>','boost','sabotage','fog','awakened'*/] } ] } ],
  events: [ { tick, kind:'phase'|'event'|'ability'|'crit'|'overtake'|'chat'|'finish'|'awakened'|'wall', runnerId|null, text, severity:'info'|'good'|'bad'|'epic', hidden?:true, data?:{} } ],
  results: [ { runnerId, place, finishTick /*float*/, timeSec, margin, wallHit, xp, spOwner, spBacker, statChanges:{stat:delta}, energyDelta, fatigueDelta, moodAfter, abilityActivations:[{tick,id,text}], majorEvents:[eventId], levelUps:0 /*set by finishRace; not hashed*/ } ],
  bets: [], hypeBefore, hypeAfter, totalTicks,
  summary: { winnerId, winnerName, photoFinish, forestAwakened, eventsCount, critsCount, upset, upsetOdds }, hash }
```
`ticks[0]` is the starting line (all `d = 0`). `pos` arrays are in **lane order** every tick. Ranks are computed per tick (ties by lane). A finished runner keeps `d = distance`.

### `SD.hype` (hype.js) — `add(state, amount, { by, reason }) → { value, crossed:[thresholdId] }` (emits `hype:changed`, `hype:threshold`), `tier(value) → 0|1|2|3`, `decayAfterRace(state)`, `idleDecay(state, elapsedMs)`, `nextThreshold(value)`.

### `SD.seasons` (seasons.js) — `advanceDay(state, rng)`, `resetDay(state)`, `endSeason(state) → summary`, `startSeason(state)`, `summary(state)`, `refundBets(state, reason)`, `refundEffects(state)` (summary shape: **M5 additions**).

### `SD.game` (game.js) — the director; every method wraps `SD.state.mutate`.
- Event timing (**clarified in review batch 7**): events a method queues through `commit()` (`race:*`, `runner:*`, `season:*`, `event:day` …) are emitted after the mutation completes; events emitted by the hook modules it calls inside the mutation (`bet:resolved`, `hype:changed` / `hype:threshold`, `player:sp`, `log:entry`, nested `achievement:unlocked`) fire at once, mid-mutation, and arrive first (see **Review fixes → Batch 7**).
- `init(opts?)` — subscribes to `race:playbackDone` → `finishRace()`, then runs `afterLoad(opts)` (**CHANGED in review batch 7**: `opts.deferPending` leaves a race saved as `'finished'` for `applyPending()`; returns `{ ok, pending }`). New `afterLoad(opts?)` and `applyPending()`: see **Review fixes → Batch 7**.
- `startRace({ distance?, runnerCount?, seed? } = {}) → { ok, message, record? }` — refuses if a race exists. Selects field (from the field seed, as `previewField`), builds entrants, simulates on the gate seed (field seed + fresh `SD.entropy`, drawn here after bets close; the field seed itself without a source or with a fixed seed; review batch 5), sets `currentRace = { record, status:'countdown', startedAt }`, re-salts `meta.seedSalt` with fresh `SD.entropy` (review batch 5; no-op without a source), emits `race:started { record }`. **Does not** reference playback; the UI's playback module listens for `race:started`.
- `setRaceStatus(status)` — used by playback for `countdown → running`.
- `pauseRace() / resumeRace()` — flips status, emits `race:paused` / `race:resumed`.
- `endRace()` — emits `race:endRequested` (playback jumps to the end and then emits `race:playbackDone`). In Node (no playback) `endRace()` calls `finishRace()` directly if `SD.playback` is undefined. **CHANGED in review batch 9**: a paused race is resumed first (`race:resumed`); see **Review fixes → Batch 9**.
- `finishRace()` — applies `record.results` to runners/players, resolves bets, hype decay, pushes to `raceHistory`, clears `currentRace`, may auto-advance day, emits `race:finished { record, results, bets, levelUps, achievements }`.
- `abortRace()` — refund bets, drop record, emit `race:aborted`. (The gate's Chaotic / Fired Up moods live only on the entrants since review batch 4, so nothing needs restoring.)
- `trainRunner(runnerId, stat, by) → result`, `restRunner(runnerId, by) → result` (used by roster card buttons and by `!train`/`!rest`).
- `triggerDayEvent(id?) → event`, `addHype(n, by?)`, `spawnRunner({ name? }) → runner`, `nextDay()`, `resetDay()`, `resetSeason()`, `resetAll()` (**CHANGED in review batch 8**: keeps the wiped game as `spiritderby.backup`; returns `backedUp`), `retireRunner` / `renameRunner` / `deleteRunner` / `removePlayer` / `purgeDemo` (review batch 8, see **Review fixes → Batch 8**), `updateSettings(patch)` (validates; emits `settings:changed`), `tickClock()` (call every 30 s from UI), `seedForRace() → uint32` (the next race's field seed, which the paddock preview draws from; with an `SD.entropy` source the race runs on a gate seed, so it is not the next `record.seed`), `replayLastRace() → { ok, sameHash }` (re-simulates last record with stored inputs and compares hashes).

## Core implementation notes (M1 core; additive unless marked CHANGED)

**Shapes and semantics the UI can rely on**
- `state.season.activeDayEvent` is a day-event **id string** (e.g. `'fogOfTheHollow'`); resolve it with `SD.events.dayEventById(id)` or `SD.state.dayEvent()`.
- `runner.energy` / `runner.fatigue` may be **fractional** (passive regen every 30 s). Round for display. `fatigue` is hidden (0..120); chat sees `runner.condition`.
- RaceRecord tick precision: `d` 0.01 m, `v` 0.1 m/s, `st` 0.01. Unchanged `fx` arrays share one frozen empty array: treat `fx` as read-only.
- **fx tags** (present on every tick the effect is active): `crit`, `ability`, `boost` (chat boost or backfired sabotage), `sabotage`, `event:<raceEventId>` (e.g. `event:looseShoe`), `fade` (stamina ≤ 12%), `wall` (≤ 3%), `fog` (on every runner while Mysterious Fog is active; hide positions), `awakened` (Forest Awakened glow).

### `SD.commands` (js/commands.js)

## M4 additions (advanced race systems + balance) — additive unless marked CHANGED

### Balance model (CHANGED, plan §5.1 / §6.6)
Goal from the brief: stats matter substantially, randomness influences races without overriding investment, and mood / condition never decide a race on their own. Before M4 the engine was nearly deterministic at race level (slope 0.24, ~1.6% race-level noise), so a 2–5% condition + mood gap beat 20 stat points: in the brief's 4-runner case Velvet Comet (best stats, Good + Sleepy) won 0.9%, and 48% when made Happy + Excellent.
- **Stats**: `RACE.PERF_SLOPE` 0.24 → **0.5** (10 phase-weighted perf points = 5% speed). `SD.race.coreOf(perf) = 1 + PERF_SLOPE × (perf − PERF_PIVOT) / 100`.
- **Race-level randomness** roughly doubled: per-race "day" form `FORM.AMP` 0.04 → **0.08** (sd ≈ 2.8%); in-race swing `NOISE.SIGMA` 0.12 → **0.20**, `SEGMENT_TICKS` 6 → **a per-distance table {1200: 8, 1600: 10, 2000: 12, 2400: 15}** (a number still works; read through `SD.race.segmentTicks(distance)`, so every race has ~20 swings and the race-level luck is about the same at every distance), new **`NOISE.RHO` 0.65**: each new segment is `seg = RHO × seg + sqrt(1 − RHO²) × sigma × tri()` (AR(1); still one rng draw per segment, `RHO = 0` reproduces the old i.i.d. segments), so good and bad spells last ~30 ticks and do not average out. In identical-clone fields the best-form clone wins ~42% (not a coin flip, not decisive).
- **CHANGED semantics — condition and energy scale effective stats, not velocity**: `core[p] = coreOf(perf[p] × SD.race.raceStatMult(entrant))` with `raceStatMult(e) = conditionRaceMult(e.condition) × energyMult(e.energy, e.maxEnergy)`. The band values are unchanged (Excellent 1.03, Good 1.01, Normal 1.00, Tired 0.96, Exhausted 0.90; energy below half down to ×0.92) and the velocity product no longer contains them. An Exhausted average runner loses ~5 perf points (≈ 2.6% speed); a well-trained Tired runner can still beat a weak fresh one. (As plain velocity multipliers, 0.90 vs 1.03 = 12.6% would need ~13% race noise for the "Exhausted clone ≥ 2.5%" target, which would erase stats.)
- **Moods** (`DATA.MOODS[m].vel`, race-level effect ≤ ±0.6%): Happy +0.4% all phases; Determined +1.2% FINAL_TURN + FINAL_STRETCH; Fired Up +2% START + EARLY (drain ×1.05); Sleepy −1% START only (drain ×0.95, regen ×1.3); Nervous −0.4% (σ ×1.2); Chaotic 0 (σ ×1.3, was 1.5; crits ×1.5). Descriptions updated.
- **Stamina**: pool = `(STAMINA.BASE + sta / STA_DIV) × POOL_SCALE × DIST_FACTOR` with `BASE` 0.9 → **0.5**, `STA_DIV` 100 → **50** (Stamina counts double; a 40-Stamina pool is unchanged) and `DIST_FACTOR` {1200: 0.92, 1600: **1.02**, 2000: **1.10**, 2400: **1.20**} (was 1.04 / 1.20 / 1.40). Nobody tires at 1200 m; at 2400 m low-Stamina, faster runners fade (Ember Tail every race, wall ~1 in 3 even with Second Wind; Glow Wisp / Thunder Fern often), Moonhoof never. `DRAIN_SCALE` 0.815 unchanged.
- **Odds refit** (maximum likelihood, 24,000 races: roster fields + mixed fields at levels 1–8 with random condition / mood / energy): **`ODDS.TEMP` may now be a per-distance table** {1200: 6.28, 1600: 5.77, 2000: 5.44, 2400: 5.23} read through `SD.race.oddsTemp(distance)` (a number still works); `REMAIN_PTS` 10.41, `SHORTFALL_PTS` 8.86, `REMAIN_CAP` 0.38, `SAFE_REMAIN` 0.14, new `STYLE_PTS` and `ABILITIES[*].rating`. `oddsFeatures().formPts` = `perfAvg × (raceStatMult − 1)` + (mood + cheer + wild-roll mean) × 100 / PERF_SLOPE. Roster calibration: mean |implied − actual| 0.5–1.4 pp per distance (was 1.2–2.5); mixed fields: every probability bucket within ~1.5 pp.
- Style tables, `CONDITION.BANDS`, crits, events and ability magnitudes are unchanged (style clones stay 22–29% per style at every distance).
- The sensitivity targets hold at every distance, not just the default 1600 m harness distance (e.g. +8 every stat 36.6% @1200 → 42.1% @2400; Chaotic ≤ 14.4%; Good ≥ 9.3%).

Measured (tools/balance-test.js, 8-runner clone fields, 2000 races @1600 m): identical clones 11.1–13.5%; one clone Good 11.7% / Tired 7.9% / Exhausted 4.2% (others Excellent); one clone Determined 13.5% / Nervous 10.2% / Fired Up 12.8% / Sleepy 10.0% / Chaotic 14.1% (others Happy); +20 Speed 32.3%; +8 every stat 37.3%; +20 Stamina 24.3% @1200 → 29.6% @2400. Brief's 4-runner case @1200 m: Thunder Fern 24.5%, Moonhoof 21.2%, Moss Runner 24.3%, Velvet Comet 30.1% (35.7% when Happy + Excellent). Roster averages over the matrix 6.4% (Bramble Jack) – 21.3% (Velvet Comet); Ember Tail 14.3% @1200 → 4.9% @2400, Moonhoof 13.1% → 17.9%.

### Race engine additions (js/race.js, js/game.js)

The leader's final stretch plays in ~1–2 s at every distance.

### Batch 3: Prototype-safe maps for user-controlled keys
Maps looked up with chat words, logins, command arguments, settings keys or save-file keys were plain object literals, so a key named like an `Object.prototype` member resolved to the inherited member: `!constructor` / `!__proto__` ran `Object` as a command handler and crashed (an error reply, a toast, a bridge reply and a `warn` log line per message, with no cooldown, so spam wiped the 300-line event log); the logins `constructor` / `__proto__` resolved to `Object` / `Object.prototype` in `state.players`, passed the player gate, committed hype / training with no cooldown and then crashed, and `__proto__` wrote `isMod`, `lastSeen`, `runnerId` … onto `Object.prototype` (after which every bridge frame without `isMod` inherited mod rights); `!ribbon constructor` charged 100 SP and stored the `Object` function; `!lb constructor` replied with an empty message; `SD.game.updateSettings({ toString })` stored junk and `{ hasOwnProperty }` threw; `training.normalizeStat('constructor')` returned `Object`.

- **New helpers** (`js/namespace.js`): `SD.util.hasOwn(obj, key)`, `SD.util.own(obj, key)` (the value only when it is an own property, else `undefined`), `SD.util.setOwn(obj, key, value)` (stores an own, enumerable data property, also for `'__proto__'`, and returns `value`), `SD.util.dict(src?)` (an `Object.create(null)` map, optionally filled from `src`'s own keys). - **Commands — CHANGED** (`js/commands.js`): the registry, the alias map, `BUILTIN_ALIASES` (exported, now a `dict`) and the source list are `dict`s, so `!constructor`, `!__proto__`, `!help constructor`, `SD.commands.get('constructor')` (was a throw), `cooldownLeft(…, 'constructor')` and a `source: 'constructor'` behave like any unknown word (`Unknown command … — try !help`, `No command called …`, `null`, `0`, source `sim`). ### Batch 4: Betting integrity and economy correctness
A bet kept the odds quoted at placement while the race could still change before the gate (a free `!rest` on a tired runner, `!snack` / `!boost` / `!cheer`, the hype tier, the gate's mood roll, a smaller field, a mod's `!race <distance>`), the 1.3x minimum odds turned bets on dominant favourites into guaranteed profit, and the odds ignored the hype tier (a max bet on the longest price at Forest Awakened @2400 m returned 1.2+ SP per SP). This batch makes every bet settle at a price the book would offer for the race actually run.

- **Odds — CHANGED** (`js/race.js`, `js/config.js`): `odds = min(ODDS.MAX, HOUSE / p rounded DOWN to 0.1)`, never raised: the **1.3x floor is gone** (`ODDS.MIN` is now **1.1**, the shortest price a bet is taken and settled at; a runner priced under it is *odds-on* and takes no bets). New `ODDS.FLOOR` (1.0) is only the shortest price shown (such a runner is below `MIN`, so nothing is ever paid at it). New export `SD.race.oddsFor(p)`. Every bettable price returns at most `HOUSE` (0.85) per SP.
- **Hype-aware odds — CHANGED**: `buildEntrants` / `assignOdds(list, distance, ctx?)` / `ratingOf(e, distance, ctx?)` / `oddsTemp(distance, hypeLevel?)` read the hype level: new `ODDS.HYPE_TEMP { LOUD: 1.04, FERAL: 1.08, AWAKENED: {1200: 1.10, 1600: 1.10, 2000: 1.20, 2400: 1.20} }` multiplies the softmax temperature per tier (new export `SD.race.hypeTempMult(hypeLevel, distance)`), and at Forest Awakened every runner's expected reserve gets new `ODDS.AWAKEN_REMAIN` (0.15, the final-turn refill). Fitted by maximum likelihood on simulated mixed + roster fields at hype 30 / 60 / 110. Below `RACE.HYPE.LOUD` the odds are exactly the M4 calibration (the balance suite's hype-0 checks are unchanged).
- **Boosts / sabotages in the odds — additive**: `buildEntrants(…, { chatEffects: [{ runnerId, type:'boost'|'sabotage', count? }] })` adds each queued effect's expected perf points (`SD.race.chatEffectPts(list, effects, distance)`: `BOOST × BOOST_TICKS` or the backfire-weighted `SABOTAGE` / `BACKFIRE_BONUS` × `SABOTAGE_TICKS`, over the race's nominal ticks, with the engine's caps). Cheers were already priced. Not stored on the entrants; `startRace` and `betting.fieldOdds` pass them (the field-odds cache key includes them).

It logs "Odds shortened at the gate: …" / "… is odds-on at the gate …", emits new **`bet:locked { recordId, bets:[copies], repriced:[{ …bet, quoted, odds }], refunded:[{ …bet, reason:'nonStarter'|'oddsOn', gateOdds? }] }`** (`SD.EVENTS.BET_LOCKED`) and returns `{ locked, repriced, refunded }` (was the refunded array). `SD.game.startRace` returns it as `result.bets`; a mod's `!race` reply adds `(n at shorter gate odds)`, and the chat panel prints a system line for re-priced and odds-on bets. No stored-shape change: the settled price overwrites `bet.odds`; the quote only travels in the event.
- **Bets count when settled — CHANGED**: a bet counts once, when the finished race settles it: `resolve()` does `recordAction(…, 'bet')` (stats.bets / participation); new **`creditBetHype(state, settled)`**, called by `finishRace` after the post-race decay, adds hype `GAINS.bet` (× hype multiplier, with hype credit) per settled bet, so bet hype builds toward the **next** race (the race that just ran was simulated with the hype it had at the gate, so a threshold crossed by bets is never announced for a race that lacked it); **High Roller** unlocks on `bet:resolved` (tagged with the race's `recordId`, so it is listed with the race results). Placing, replacing and cancelling bets counts nothing, and neither does a race that is aborted (`abortRace`) or interrupted (`recoverInterruptedRace`), whose bets are refunded: bet / cancel cycles and abort / reload farm no stats, hype or +50 SP. `lockForRace` counts nothing. `CONFIG.BETTING.COUNT_REPLACEMENTS` is **removed**. Balances and `payout` / `net` are unchanged. `player:sp` fires twice for a win (`betStake` refund, then `betWin`).
- **Mid-race `!cheer` — CHANGED** (`js/commands.js`, `js/players.js`): a cheer while a race is locked counts as a cheer (hype, SP, stats) but never sets backing; `players.recordAction` also leaves backing alone whenever `state.currentRace` exists (the result is already decided). No backer SP or race victory for cheering the visible leader.

So `abortRace` and `persistence.recoverInterruptedRace` leave no gate moods behind, with no stored field to restore. Race results and hashes for the same inputs are unchanged.

### Batch 5: RNG entropy, seed secrecy and replay safety
The only entropy in the whole game used to be the creation time: `meta.seedSalt = hash('spirit-derby:' + createdAt)` (32-bit), and every race seed was `seedFrom(salt, season, day, raceCounter)`. A viewer could brute-force the salt from a few paddock lane orders, invert FNV-1a from one race seed in a pasted COPY LAST RACE JSON, or simply wait for a save rollback (an older export imported, a stale second window) to replay races chat had already watched, and bet on the known winner. Refused trainings also advanced the shared action RNG for free, and the debug seed override was saved and invisible on stream.

- **`SD.entropy` — new** (`js/namespace.js`): `next() → uint32 | null`, `set(fn)`, `reset()`, `available()`. The core's only source of fresh randomness, injected like `SD.clock` (the core still never touches `crypto` / `window` / `Math.random`). **`js/main.js` installs `crypto.getRandomValues`** (a `Math.random` ^ `Date.now()` fallback only where `crypto` is missing) before boot. With no source (Node, every test suite) `next()` is `null` and every path below behaves exactly as before, so all seeds, hashes and suites stay reproducible.
- **Seed salt — CHANGED** (`js/state.js`): `create()` without `opts.seedSalt` draws the salt from `SD.entropy` (the creation-time hash is only the no-source fallback). New **`SD.state.resalt(state, tag) → boolean`**: `meta.seedSalt = (seedFrom(oldSalt, 'resalt', tag) + entropy) >>> 0`, a no-op returning `false` without a source.
- **Re-salted at every race start, load and import — CHANGED**: `SD.game.startRace` re-salts right after the race's own seed is drawn (so the next paddock, `seedForRace()` and every later seed are independent of this record's seed; the preview is still exactly the next field, since nothing re-salts between races except a load / import); `persistence.load()` and `importJSON()` re-salt the loaded state (`freshSeeds`), so a rolled-back save never replays watched races, and two copies loaded from the same save diverge. Stored RaceRecords keep their own `seed`, so `replayLastRace`, `SD.debug.replay()` and COPY LAST RACE JSON still reproduce past races exactly. A debug seed override still wins over the salt.
- **Gate seed — CHANGED** (`js/game.js` `startRace`, review batch 5 fix round 1): re-salting alone was not enough. The paddock shows the next field in lane order before bets close, and that lane order carries about log2(n!) bits of the field seed (21.8 for 10 runners, plus the field membership when energies are close, e.g. the rested first race of a day), so a viewer could brute-force the field seed itself over all 2^32 values in under a minute on a desktop, no salt needed, and simulate the race. So the field seed (`seedFrom(seedSalt, season, day, raceCounter)`, `seedForRace()`) now draws only the field and the lane order (`previewField` is still exactly the real field), and the race runs on a **gate seed** = `(fieldSeed + SD.entropy.next()) >>> 0`, drawn inside `startRace`, i.e. after bets have closed. The gate moods and the track name come from `seedFrom(gateSeed, 'gate')`, the simulation from the gate seed itself, and the record stores the gate seed as `record.seed` (so replays and COPY LAST RACE JSON still reproduce it). Knowing the field seed therefore tells a viewer nothing about the result. Without a source (Node, tests), or with a fixed seed (debug override, explicit `startRace({ seed })`), the gate seed is the field seed and every draw is as before, so all suites and debug seeds reproduce.
- **Per-action randomness — CHANGED** (`js/game.js` `actionRng`): training rolls, SPAWN RUNNER / `!create` rolls, day events and season rolls add a fresh `SD.entropy` value to `seedFrom(seedSalt, tag, actionCounter)`, so they can be neither predicted from the counter nor replayed by a rollback. Unchanged without a source.
- **EXPORT JSON — CHANGED** (`js/persistence.js`): `exportJSON()` leaves out `meta.seedSalt` and writes `settings.seedOverride: null` (plus the batch 1 token redaction). Importing such a file gets a new salt (`normalize` fills a missing salt from `state.create`, i.e. `SD.entropy`, then the import re-salts). `spiritderby.save` / `spiritderby.backup` still hold the salt (they never leave this PC). export → import is lossless except for the salt. COPY LAST RACE JSON (`SD.debug.lastRaceJSON`) was never carrying the salt; its race seed is now harmless because later seeds do not derive from it.
- **Refused trainings — CHANGED**: new `SD.training.refusal(runner, stat) → { ok:false, message } | null` (retired, unknown stat, energy under `TRAINING.MIN_ENERGY`, stat at its cap), used by `train()` and checked by `SD.game.trainRunner` **before** its commit: a refused train no longer advances `meta.actionCounter` (so spamming `!train <maxed stat>` cannot steer the next roll into a crit), and emits no `state:changed` / save. The `!train` handler throws its refusal as a `CommandError`, so the command's own mutate emits nothing either (reply, severity and the no-cooldown behaviour are unchanged).
- **Debug seed override — CHANGED**: `settings.seedOverride` is session-only. `save()` writes the state with `seedOverride: null` (new internal `forStorage(st)`), `exportJSON()` too, and `load()` / `importJSON()` clear an override stored by an older build (v1.0.0 saved it) with a log line "The debug seed override (N) was cleared …". While it is active the header race line shows **FIXED SEED** (`.hdr-fixedseed`; just FIXED at 1440 px and below, so the day-event pill keeps its room), in overlay mode too. `settings.debug` itself is still saved.
- **`hashRecord` — CHANGED** (`js/race.js`): `results[].levelUps` is hashed as `0` (a `JSON.stringify` replacer), the value `simulate()` hashed, because `finishRace` writes the real level-ups into the stored results. Every hash `simulate()` produces is unchanged (no `ENGINE_VERSION` bump), and `hashRecord(storedRecord) === storedRecord.hash` now holds, also for records stored by older builds.
- **`rollStats` — CHANGED** (`js/runners.js`): the remainder loop indexes `order[j++]` from 0, so the most-favoured stat gets the first leftover point (it never got one). No rng draw changes; spawned / `!create` runners' stats can differ by a point from before.
- **No stored-shape change**: `SCHEMA_VERSION` stays 3; `meta.seedSalt` stays a uint32 in the save. v1 / v2 / v3 saves, exports from earlier builds (with a salt) and `tools/fixtures/save-m1.json` load as before (then re-salted in the browser).
- **Tests**: new suite **`tools/rng-test.js`** (`rng` in `tools/run-tests.js`): the `SD.entropy` hook, the salt source, the FNV-1a inversion of a leaked seed (predicts the next race without entropy, never with it), re-salting at every race start with the paddock preview still the real field and every race replaying to its hash, the gate seed (a brute force of the field seed from the paddock lane order over a reduced seed space finds it, and predicts the whole finish order without entropy but never with it; the same state and paddock with different gate entropy give different races), no salt / override in EXPORT JSON or COPY LAST RACE JSON, no repeated seeds after importing an older export or reloading an older save (and reproducible reloads without entropy), per-action entropy for training and spawns, refused trainings (counter, `state:changed`, cooldown, no steering of the next roll), the override never saved or loaded, `hashRecord` of stored records, the `rollStats` remainder order. `tools/persistence-test.js` (**changed assertions**: export → import compares everything but `meta.seedSalt`, which an export no longer carries; the IMPORT backup is compared with the full live state instead of `exportJSON()`).

### Batch 6: Persistence durability (size, quota, second window, backups)
A long chatty career outgrew the ~5.2M-character per-origin localStorage quota (every history record kept one bet and two chat-effect copies per viewer, and `save()`'s quota retry only dropped 8 tick logs), after which every save failed with only a console warning and a reload silently rolled the game back. Every command, even `!status`, rewrote the multi-MB save twice a second, mid-race too. A second window opened "just to look" cancelled and refunded the race it saw and overwrote the live save through its 30 s clock. Backup writes failed silently, an unreadable or newer save was replaced by the fresh game's first autosave, and viewers were never pruned.

- **Slim history records — CHANGED, schema 4** (`js/persistence.js`): `trimHistory(state, keepFull?)` drops `inputs.raceEffects` from every history record and runs the new **`slimRecord(rec)`** on every record past `CONFIG.HISTORY_FULL_LOGS`: `ticks: []` (`ticksStripped`), `inputs.chatEffects` → **`SD.race.compactChatEffects(list, runnerIds)`** (new, `js/race.js`: drops entries the engine skips - runners not in the race, boosts / sabotages past the caps - and merges each runner's cheers into one entry, so the simulation, its RNG draws and its hash are identical; only replayed commentary names differ), `bets` → the `CONFIG.SAVE.BETS_KEPT` biggest winning bets plus **`betsSummary { count, won, staked, paid }`** when any were left out, cheer events' `data.names` capped at `CONFIG.SAVE.NAMES_MAX` plus **`data.namesMore`**, and **`slim: true`**. A slim record weighs ~11K characters whatever the crowd (a whole one grew by ~300 per viewer). `SCHEMA_VERSION = 4`; **`MIGRATIONS[4]`** normalizes, slims existing records and logs "Save upgraded to schema v4 …". Every stored record still replays to its hash; the last `HISTORY_FULL_LOGS` records (REPLAY / COPY LAST RACE, the results modal) stay whole.
- **Size budget — new** (`save()`): new internal **`fitBudget(state, excess)`** (exported for tests) shrinks the state, cheapest loss first: every record but the last 2 slimmed, the oldest records dropped down to `CONFIG.SAVE.MIN_HISTORY` (20), the log cut to 50 lines, then records down to the last one. Players, runners, balances, bets and the season are never touched. `save()` applies it when the JSON is over **`CONFIG.SAVE.BUDGET_CHARS`** (2,400,000: the save plus a same-size backup fit Chrome's / OBS's quota), trimming to 90 % of it, and when the browser refuses a write it retries up to 3 times, shrinking by 10 / 30 / 60 %. **Fix round:** step 1 sticks: `trimHistory` keeps only the last 2 records whole once a slim record sits inside the last `HISTORY_FULL_LOGS` (older than the last 2), so the slimmed tick logs no longer grow back (+~80K per race) and eat the headroom; a long career then grows one slim record (~11K) per race and trims about every 20 races (a 1600 m, 6-runner career: first trim near race 170, then every ~22 races, history 165-190 records). A trim writes a log line ("The save was getting too big for browser storage …") and `state:saved` gains **`trimmed: { races, logs, log, routine } | null`**: `routine` (only old records dropped and at least **`CONFIG.SAVE.ROUTINE_HISTORY`** = 100 kept) logs at `info` and main.js shows no toast; a deeper trim or a quota retry logs `warn` and toasts once per session. **Fix round 2:** `save()` trims a working copy (its own `raceHistory` / `log` arrays; `fitBudget(state, excess, { copy: true })` clones a record before slimming it) and the live game takes the trimmed history and log, with the log line and its `log:entry`, only once that copy is written. Only a quota error (`QuotaExceededError`, `NS_ERROR_DOM_QUOTA_REACHED`, code 22 / 1014) gets the smaller retries; any other write error fails at once. A save the browser keeps refusing therefore loses nothing in memory (before, each retry and each `RETRY_MS` retry cut the live history and log deeper, down to 1 record, and the first save that worked again wrote that over the stored game), and EXPORT JSON still has everything.
- **Save failures are visible — new**: a failed save sets `dirty` (so `flush()` / the next autosave retry; it used to stay clean and a reload lost the game), emits **`state:saveFailed { at, error, bytes, stats }`** (new `SD.EVENTS.STATE_SAVE_FAILED`), backs autosave off for **`CONFIG.SAVE.RETRY_MS`** (15 s: no double stringify every 500 ms) and schedules its own retry. main.js toasts it (at most once a minute) and the header shows **⚠ NOT SAVED** (`.hdr-savewarn`), in overlay mode too. `stats()` gains `failedAt`, `role`, `readOnly`, `reason`, `backup` / `rescue` (sizes) and `budget`.
- **Save pacing — CHANGED** (`js/state.js`, `js/commands.js`, `js/game.js`, `js/persistence.js`): new **`SD.state.saveHint('lazy' | 'none')`** (see `mutate`). **`scheduleSave({ lazy })`**: a lazy save, or any save while a race is in progress (countdown / running / paused), waits **`CONFIG.SAVE.LAZY_MS`** (60 s) instead of `SAVE_DEBOUNCE_MS`; `finishRace` / `abortRace` save at once as before, and a pending later timer is pulled forward by a normal change, never pushed back. In Node a lazy save only marks the game dirty. New command def flag **`lookOnly`** (`!status`, `!inspect`, `!help`, `!leaderboard`, `!rank`, `!bets`, `!odds`, `!hype`, `!achievements`; `publicDef` shows it): the pipeline hints `'lazy'` (only `lastSeen` / the command count changed) or `'none'` (no player touched), and so does a handler that set `ctx.readOnly`; a daily bonus is saved normally. `tickClock()` hints `'none'` when nothing changed and `'lazy'` for energy regen / hype decay, so an idle window never rewrites the save.
- **One writer per storage — new**: **`spiritderby.lock = { id, n, at }`** names the window that saves (instance id from `SD.entropy`, or a clock hash in Node; `n` counts its writes). `load()` makes a window a **reader** when another window's lock is younger than **`CONFIG.LOCK.STALE_MS`** (90 s): the game is loaded as stored - a race that window has running is **not** cancelled or refunded - and nothing is ever written (`save()` / `flush()` / `clear()` / `importJSON()` refuse; `result.readOnly: true`). A writer stamps the lock on every save and on **`heartbeat()`** (main.js, every **`CONFIG.LOCK.HEARTBEAT_MS`** = 10 s and on `storage` events); when it finds another window's lock it steps down to reader and emits **`state:readOnly { role, readOnly, reason:'other-window', message, otherAt, free }`** (new `SD.EVENTS.STATE_READ_ONLY`). New API: **`role()`**, **`lockStatus()`**, **`heartbeat()`**, **`takeOver()`** (claims the lock and reloads from storage; returns `load()`'s result plus `ok`), **`release()`** (main.js on `pagehide`; **fix round:** it marks the lock `{ …, released: true }` instead of removing it: the next window that loads - normally this same window reloading - becomes the writer at once, while a reader's `lockStatus()` reports the released lock `free` only after **`CONFIG.LOCK.RELEASE_GRACE_MS`** (8 s) with **`freeIn`** (ms left) meanwhile; before, a read-only tab took the role within milliseconds of an F5 and the reloaded saving window came back read-only and off chat), **`instanceId()`**, `_setInstanceId(id)` (tests), `LOCK_KEY`. main.js: a reader shows the save banner (`.savebar`, **TAKE OVER**), never auto-connects to chat, disconnects when it steps down, and takes over by itself when `heartbeat().free` (the other window released its lock more than `RELEASE_GRACE_MS` ago, or went stale), checking again after `freeIn`.
- **Held saves — CHANGED** (lifecycle-concurrency#12): an unreadable, newer-schema or failed-upgrade save is left untouched in `spiritderby.save` (role **`'held'`**, nothing is written) and `load()` returns **`held: true, error`**; the fresh game's log says so. The banner offers **DOWNLOAD SAVED GAME** (`heldText()`) and **START NEW GAME** = **`releaseHeld({ force? })`**: the stored text is first copied to **`spiritderby.rescue`** (`RESCUE_KEY`, read back to check; refused with `rescueFailed` when there is no room, unless `force`), then the window becomes the writer and saves. An import while held rescues the same way. `readRescue()`; the admin Save section has **⬇ RESCUE COPY** and (fix round) **✕ DELETE RESCUE COPY** = **`discardRescue()`** (false in a read-only window): the copy shares the per-origin quota with the save and its backup. A migration or import never writes over the rescue copy.
- **Checked backups — CHANGED** (persistence#3, persistence#6): internal `writeBackup(text)` reads the copy back. `load()` reports a failed pre-upgrade backup as **`backupFailed: true`** (log line + main.js toast). **`importJSON(text, opts?)`** now returns `{ ok:true, migratedFrom, ignoredConnection, backedUp }` or `{ ok:false, error, readOnly? | backupFailed? | rescueFailed? | saveFailed? }`: it refuses without a checked backup of a non-blank current game (`opts.force` overrides: the admin drawer downloads the current game first, then forces), never backs up a blank game (no race run, no viewer) over an existing backup, and when the imported game cannot be saved it puts the current game back and fails with `saveFailed` (it used to report success while the old game stayed stored). **Fix round:** it first checks `stillWriter()` (a window another one just took over from refuses with `readOnly` before touching `spiritderby.backup`), and a failed save also puts the backup slot back as it was (removed when there was none), so a RESTORE BACKUP whose save is refused no longer loses the game it was restoring. New **`restoreBackup(opts?)`** (admin **↺ RESTORE BACKUP**) imports `spiritderby.backup` with `opts.restore` (log "Backup restored.", `state:loaded { source:'restore' }`); the replaced game becomes the backup, so a restore can be undone.
- **Retention — new** (`js/players.js`, `js/seasons.js`): **`SD.players.prune(state, now?) → removedKeys[]`**, run by `SD.seasons.advanceDay` at every day change (both branches; `season:dayAdvanced` / the day info gain **`pruned`**, and a log line names the count). ### Batch 7: Import and normalisation hardening, boot robustness
An imported (hand-edited or tool-made) save was only checked shallowly. A race saved as `'finished'` with a thin record passed `isValidRecord` and crashed `game.init()` on every later boot, and IMPORT never applied a good one, which left START refused and the drawer locked until a reload. A primitive `runner.record.bestTimes` made `finishRace` throw half-way, a numeric runner id broke every lookup by name, an entrant `lane` went into the track's HTML raw and a huge `distance` hung the ruler loop. Runtime maps outlived RESET ALL / IMPORT, a `state.set()` inside a mutation stopped autosave for good, and the boot order lost a pending race's achievements and results modal.

- **One post-load routine — new / CHANGED** (`js/game.js`): **`SD.game.afterLoad(opts?) → { ok, pending, dayEventRolled }`** runs on the game that was just `SD.state.set()`:
  - `opts.resetRuntime` → `SD.state.resetRuntime()` + `SD.betting.clearCache()`;
  - a race saved as `'finished'` is applied (`applyPending()`) unless **`opts.deferPending`**;
  - a missing day event is rolled; `runtime.lastClockAt = now`.

  It is used by **`init(opts?)`** (boot, TAKE OVER, tests; **CHANGED**: returns `{ ok, pending }`; since review batch 8 fix round 1 TAKE OVER passes `{ deferPending: true }` and calls `applyPending()` after `state:loaded`, like IMPORT), by **`persistence.importJSON`** (IMPORT JSON / RESTORE BACKUP: `{ resetRuntime: true, deferPending: true }`, then `state:loaded` + `state:changed`, then `applyPending()`) and by **`resetAll()`** (`{ resetRuntime: true }`). **`SD.game.applyPending() → null | { ok, applied: true, result } | { ok, applied: false, cancelled: true, reason, refunded }`** applies a `'finished'` race when `persistence.recordProblem(record, true)` finds nothing and `finishRace()` does not throw. Otherwise it cancels the race like an abort (bets refunded, paid effects queued again, `race:aborted`), logs "A race saved as finished could not be applied (…)" and never throws. `importJSON` returns **`pendingRace: 'applied' | 'cancelled' | null`**.
- **Deep checks on load / import — CHANGED** (`js/persistence.js`, `normalize()`): new **`SD.persistence.recordProblem(record, finished?) → reason | null`**. It requires a string id, entrants with unique string runner ids and integer lanes 1..max(`MAX_RUNNERS`, entrant count), and a bounded distance. With `finished` it also requires a `summary` object and non-empty results, each for an entrant, with numeric `place` (integer ≥ 1), `timeSec` (> 0), `xp` (≥ 0), `energyDelta` and `fatigueDelta`, `statChanges` only on `CONFIG.STATS` keys, and `spOwner` / `spBacker` ≥ 0. A race in progress it rejects becomes an interrupted one (`{ record, status: 'running', malformed: reason }`), which `recoverInterruptedRace` refunds with the log line "The race saved in progress could not be used (…)". **`isValidRecord`** (history; now exported) also requires object entrants / results and a distance in 100..**`CONFIG.RACE.MAX_RECORD_DISTANCE`** (new, 10000 m); history records that fail are dropped. A runner id that is not a non-empty string gets a new id (`runners.nextId`). `recoverInterruptedRace` re-queues a record's `inputs.raceEffects` through the same effect checks as the queue.
- **`runner.record.bestTimes` — CHANGED** (`js/runners.js` `normalize`): a non-object is removed (`finishRace` recreates it); an object keeps only positive integer distances with a positive finite time. `finishRace` also replaces a non-object `bestTimes` instead of throwing. `SD.state.findRunner` compares `String(r.id)`.
- **Retired runners — CHANGED** (gap1#4): `normalize()` releases a retired runner's owner (`ownerKey` / `owner` / `claimedAt` → null) and clears the `player.runnerId` / `backing` that point at it. Its open bets and queued paid boosts / sabotages are refunded at once (SP back, `stats.spSpentTotal` reversed) instead of being held until the season ends, so an orphan pebble no longer counts toward the per-race sabotage cap. Bets on unknown runners are refunded too (they used to be dropped with their stake), and the older of two bets by one viewer is refunded the same way.
- **Runtime reset — new** (director-state#3): **`SD.state.resetRuntime()`** replaces `cooldowns`, `activity`, `runnerCooldowns`, `nervousCheers` and `hypeRecent` with empty dicts and sets `activeCommand = null`, `hypeIdleAccumMs = 0`, `lastClockAt = now`; `chatFeed` and `connected` are kept. TAKE OVER loads the same game and keeps them.
- **`state.set()` — CHANGED** (director-state#8): it no longer resets the mutate depth. A `set()` inside a mutation takes effect when that mutation ends (its `state:changed` and save apply to the new state). Before, the depth went to -1 and `state:changed`, `updatedAt` and autosave stopped for the rest of the session.
- **Hook events fire mid-mutation — documented** (director-state#10): the lower-risk option was taken. Well-formed saves (v1 / v2 / v3 / v4, `tools/fixtures/save-m1.json`, `tools/fixtures/save-v2-display-names.json` with its `'finished'` race) load exactly as before; only malformed parts are repaired, refunded or dropped. `currentRace.malformed` exists only between `normalize` and `recoverInterruptedRace` (a read-only window, which does not recover, may keep it in memory but writes nothing).

### Batch 9: UI and playback fixes
A race in a hidden page (minimised window, covered by a full-screen game, another tab) ran at 10% speed or slower, so results and training stayed locked for minutes or hours. END did nothing when the race was paused in the finish hold, and END during the countdown left the status at `'countdown'`. - **Playback — CHANGED** (`js/ui/playback.js`, `js/config.js`, ui-track#1): a hidden page advances by the real elapsed time (browsers wake hidden-page timers about once a second, and once a minute after 5 minutes), capped by new **`CONFIG.PLAYBACK.HIDDEN_MAX_DT_MS = 90000`** (suspend / resume). **`CONFIG.PLAYBACK.MAX_FRAME_DT_MS` CHANGED 100 → 250**: it is now the visible (rAF) frame clamp (was a hard-coded 0.25 s) and the sub-step size. A long step runs in sub-steps of at most `MAX_FRAME_DT_MS`, so every tick, phase, record event and finish is still emitted once and in order; only the last sub-step emits `race:frame`, and a step stops when a `race:playbackDone` listener starts another race. The visible path is unchanged.
